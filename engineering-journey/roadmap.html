Learning 2026-07-04 ●●○○○

Grokking the injectable LLM port (ports & adapters)

Asked what "ports-and-adapters architecture (injectable LLM port)" actually means. Walked through SkillGuard's own port.py (the LLMJudge Protocol) and anthropic_judge.py (the concrete adapter) to see how the Detection Engine depends only on the interface, letting a real Claude adapter run in prod and a deterministic stub run in tests.

Learnings (4)
  • The Detection Engine never imports the Anthropic SDK — it talks only to the LLMJudge Protocol (a structural interface). AnthropicJudge is one adapter; a test stub is another.
  • "Injectable" means the engine receives an LLMJudge from outside rather than constructing one, so tests can pass a stub with hard-coded verdicts (no network, no API key, deterministic).
  • Python's Protocol gives structural typing: anything with a matching judge() method IS an LLMJudge, no inheritance required.
  • The pattern also quarantines the security-critical untrusted-data framing (ADR 0002) inside one adapter instead of smearing it across the codebase.
General knowledge (1)
  • Ports & adapters: Keep core logic depending on an interface (port), never a concrete external system; plug real vs fake implementations in from outside (inject). The payoff is testability — swap a non-deterministic, costly dependency (an LLM, a DB, the network) for a controlled stub without touching the core.
