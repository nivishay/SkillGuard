Design 2026-07-04 ●●●●○

SkillGuard architecture grill + engine-only PRD

Grilled a one-paragraph 'AI security for skills' idea into a decision-complete architecture (glossary, 2 ADRs, PRD, GitHub issue), walking a design tree one dependency at a time and isolating the single unproven risk into a shippable first slice.

Trade-offs (5)
  • ✔ Install-time CLI gate as surface #1 ✘ Chrome Extension or GitHub Actions interception
    The extension only catches browser-discovered skills and CI only catches repo-committed ones; the CLI gate sits at the one choke point every install path (clone/curl/zip) converges on, and stays agent-agnostic so browser/CI become later clients not rewrites.
  • ✔ Hash-first, upload-on-miss with a shared verdict cache ✘ Always upload full content, or scan fully locally
    Always-upload leaks content even for already-known skills; fully-local kills the shared cache and forces a weak on-device model. Hash-first keeps known skills private AND builds a network-effect cache where one scan protects every later developer.
  • ✔ Canonical bundle hash (LF-normalized, junk-excluded) as skill identity ✘ Raw byte hash, or source+version (repo+commit)
    User stress-tested with 'two devs download the same skill — same hash?': raw bytes diverge on Windows CRLF vs Linux LF (near-zero cache hits), source+version misses forks/mirrors. Only content-addressed + canonicalized identity makes 'same skill -> same hash' hold cross-platform, which the whole moat depends on.
  • ✔ Hybrid static + LLM detection with defense-in-depth ✘ LLM-only, or static-rules-only
    Static alone misses semantic injection ('review env config files' with no banned keyword); LLM alone is costly and can be prompt-injected by the skill it reads. Hybrid pairs a deterministic static floor the LLM can't downgrade with semantic judgment that only ever escalates.
  • ✔ Ship engine-only `skillguard scan` first ✘ Build full v1 (gate + cache + DB + provenance) up front
    Detection quality is the sole unproven risk; everything else is known plumbing. Validating the engine against an eval corpus before wrapping infra around it avoids betting plumbing on an engine that might not work.
Learnings (4)
  • An install-time CLI gate is the universal choke point for AI-skill installs, because every discovery path still has to land the skill on disk before the agent trusts it.
  • A shared verdict cache only works if identity is content-addressed AND canonicalized (LF line endings, exclude .git/OS junk) so the same skill yields the same hash across Windows/Mac/Linux.
  • Static detection is grep-on-steroids for known-bad primitives (curl|bash, ~/.ssh, base64 -d | sh) but is blind to innocent-sounding semantic injection, which is what the LLM layer is for.
  • A security analyzer's input is adversarial toward the analyzer itself: a skill can try to talk the LLM into a CLEAN verdict, so manipulation attempts must escalate the verdict, backed by a static floor the LLM can never downgrade.
